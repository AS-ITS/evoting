## 2. 環境與設定檔

### 2.1 關鍵檔案位置

| 檔案 | 用途 | 是否入版控 |
|---|---|---|
| `/.env` | 環境變數（DB 連線、SMTP、路徑等） | ❌（僅 `.env.example` 入版控） |
| `/etc/voting/master.key`（Linux）或 `C:\ProgramData\voting\master.key`（Windows） | 主金鑰 OS 預設檔；若設 `VOTING_KEY_FILE` 則改讀該絕對路徑 | ❌ |
| `config/web.php`、`config/console.php` | 應用配置 | ✔️ |
| `config/params.php` | 參數與代碼表（`ct.*`，含組織分組 preset `ct.division*Ary`） | ✔️ |
| `config/encrypted-fields.php` | 加密欄位定義 | ✔️ |

### 2.2 環境變數重點

完整說明見 [`docs/CONFIGURATION.md`](../CONFIGURATION.md)。維運最常動到的：

- `APP_ENV`：production / testing / development。**未設定會直接拋例外**，環境判斷優先吃這個值。
- `DB_*` / `TEST_DB_*`：正式庫與測試庫連線。`DB_PASSWORD` 支援密文（`ENC:` 前綴），用 `php yii encrypt/db-password` 產生。
- `APP_PATH_UPLOADS`：檔案上傳根目錄（filePool）。實際路徑為 `{APP_PATH_UPLOADS}/{APP_ID}`，底下有 `candidateFile/{voteID}/`（場次附件）與候選人照片目錄。
- `ALLOWED_HOSTS`：Host header 白名單，新增網域時要同步更新。
- `SESSION_TIMEOUT`：管理者 session 逾時（預設 7200 秒）。
- `SENSITIVE_REAUTH`：高敏感操作二次驗證（預設 `true`）。關閉後密碼/選票匯出等不再要求管理員密碼確認，**僅限測試環境**。
- `SENSITIVE_PLAINTEXT_TTL`：列表明文解鎖有效秒數（預設 900，即 15 分鐘）。

詳見 [`SECURITY.md`](../../SECURITY.md) §二次驗證。

### 2.3 主金鑰（最重要的單點）

主金鑰派生的子金鑰用於加密 `.env` 機敏欄位與**匿名投票密碼**。載入優先序：`VOTING_MASTER_KEY` → `VOTING_KEY_FILE`（若有）→ 否則 Linux `/etc/voting/master.key` 或 Windows `C:\ProgramData\voting\master.key` → `.env` 的 `MASTER_KEY`（僅開發；正式環境禁止）。

**⚠️ 主金鑰遺失 = 資料庫內所有已加密投票密碼永久無法解密，密碼函無法重印。** 詳見 [`MASTER_KEY_SETUP.md`](../MASTER_KEY_SETUP.md)。

### 2.4 配置健檢指令

```bash
php yii config/validate      # 驗證系統配置
php yii config/health        # 配置健康報告
php yii config/info          # 顯示配置資訊
php yii config/clear-cache   # 清配置快取
php yii encrypt/test         # 測試加解密（驗證主金鑰可用）
php yii migrate-passwords/verify  # 驗證投票密碼可正確解密
php yii migrate-passwords/upgrade-crypto  # Phase 2.1：v0→v1 backfill（正式環境需 ALLOW_PRODUCTION_MIGRATE=1）
```

## 3. 部署與升級 SOP

### 3.1 升級步驟（正式環境）

```bash
# 0. 前置檢查：確認沒有進行中的投票（active=1 的場次）
#    SELECT voteID, name, active FROM votes WHERE active = '1';

# 1. 備份（見第 4 節）：DB + .env + master.key + filePool

# 2. 取得新版程式
cd /var/www/html/voting
git fetch && git checkout <tag或branch>

# 3. 更新相依套件（有異動 composer.lock 時）
composer install --no-dev

# 4. 執行資料庫 migration（有新 migration 時）
php yii migrate

# 5. 清快取
php yii cache/flush-all
php yii config/clear-cache

# 6. 健檢
php yii config/validate
php yii encrypt/test
php yii migrate-passwords/verify

# 7. 目錄權限（web server 使用者需可寫）
#    runtime/、web/assets/、filePool 目錄
chown -R <web-user>: runtime web/assets

# 8. 冒煙測試：/admin 登入、建立測試場次、產生密碼、投一張票
```

`composer install` 會自動套用 [`patches/`](../../patches/)（見 [`VENDOR_PATCHES.md`](../../VENDOR_PATCHES.md)）。

### 3.2 全新安裝

依 [`SETUP.md`](../../SETUP.md) 進行；資料庫初始結構用 `docs/init_db.sql`。

### 3.3 回滾

1. `git checkout <前一版tag>`，`composer install --no-dev`。
2. 若新版有跑 migration：`php yii migrate/down <N>`（回滾步數需事先在 release note 記錄）。
3. 還原前一版 DB 備份（若 migration 不可逆）。
4. 清快取、健檢，同 3.1 步驟 5–8。

## 4. 備份與還原

### 4.1 備份對象與建議頻率

| 對象 | 內容 | 頻率 | 方式 |
|---|---|---|---|
| 資料庫 `voting` | 所有投票資料 | 每日；**選舉日投票前後各一次** | `mysqldump` |
| 主金鑰 `/etc/voting/master.key` | 加密金鑰 | 每次變更時；異地保存 | 離線保存（保險櫃/密封信封），**勿與 DB 備份放同處** |
| `/.env` | 環境設定 | 每次變更時 | 加密保存 |
| filePool 上傳目錄 | 場次附件、候選人照片、密碼函樣板 | 每日 | rsync/tar |
| nginx 設定 | 轉址規則 | 每次變更時 | 系統科管理 |

備份排程與保存地點：`TODO`（cron 排程、備份主機、保留週期）。

### 4.2 備份指令範例

```bash
# 資料庫
mysqldump --single-transaction -u<user> -p voting | gzip > /backup/voting_$(date +%Y%m%d_%H%M).sql.gz

# 上傳目錄（路徑依 APP_PATH_UPLOADS 實際值調整）
tar czf /backup/filepool_$(date +%Y%m%d).tar.gz <APP_PATH_UPLOADS>/voting
```

### 4.3 還原演練

**每年至少一次**在測試機演練：還原 DB → 放入 master.key → `php yii migrate-passwords/verify` 確認密碼可解密 → 抽查密碼函重印。備份若沒驗證過等於沒有備份。

### 4.4 選舉日快照

選舉日（投票進行中）建議每小時一次 DB 快照，重點資料表：`ballots`、`ballotsSelected`、`passwords`、`logins`、`logs`。

## 6. 選舉日應變 SOP

### 6.1 事前準備（前一日）

1. DB 完整備份 + filePool 備份。
2. `php yii config/health`、`php yii migrate-passwords/verify` 全綠。
3. 確認場次設定：投票時間(起迄)、投票狀態、場次碼、短網址、啟用密碼數量。
4. 確認 sa/va 等高權限帳號已綁定 TOTP（若已部署 migration）；`SENSITIVE_REAUTH=true`。
5. 確認各分組專屬網域轉址（若有）指向正確場次（短網址對應見使用手冊「注意事項」）。
6. 清除前次測試的登入狀態（網站管理 → 清除登入狀態）。

### 6.2 常見狀況處置

| 狀況 | 處置 |
|---|---|
| 投票者反映密碼登入失敗 | 網站管理 → LOG 查 `LOGIN_PASSWORD_FAIL`（類型 501）紀錄：含 `voteID`、失敗原因，**不含明文密碼**（2026-07 起）；常見為形近字元（0/O、1/l）；確認密碼狀態是否「啟用」；必要時經**密碼管理 → 密碼匯出**（二次驗證 + LOG 166）比對 |
| 需紙本選票對照名單 | 選票管理 → **選票統計匯出**（二次驗證 + LOG 176）：CSV 或**投票結果封存單**；匿名投票「投票者」為明文密碼 |
| 投票者被鎖定 | 匿名登入錯誤超過次數會鎖定 N 秒（網站設定可調），等待或臨時調整「匿名登入鎖定時間」 |
| 投票者換裝置無法登入（session 卡住） | 網站管理 → 清除登入狀態，針對該場次/密碼清除 |
| 頁面變慢 | 檢查 DB 慢查詢與連線數；計票展示的「資料更新間隔時間」若設太短會加重負載，可調大 |
| 需要緊急延長投票 | 編輯 → 投票時間(迄) 調整即可，立即生效 |
| 補登（紙本通信投票） | ① 清除登入狀態 → ② 投票狀態改「補登」→ ③ 依紙本建立選票；登入頁會顯示「開始進行紙本通信計票作業」 |
| 誤按重啟 | **重啟會刪除選票/計票/開票/結果**；立即停止操作並從最近 DB 快照還原（見 4.4） |

### 6.3 升級凍結

選舉日前一週凍結程式部署與 DB schema 變更，僅允許緊急修補（需 sa 核可並先在測試環境驗證）。

## 7. 帳號與權限生命週期

角色定義（`config/params.php` 的 `ct.apRoles`）：

| 角色 | 說明 |
|---|---|
| sa | 系統管理者：全功能，含網站設定、使用者管理、短網址修改 |
| va | 投票活動管理者：管理自己建立/被指派的場次 |
| ga | 群組管理者：管理群組與群組內場次 |
| gm | 群組成員：依群組設定可編輯群組內場次 |

作業流程：

1. **開通**：收 ISMS 權限申請表 → 網站管理 → 使用者管理建立帳號 → 指派角色 → 記錄於權限管理名冊。
2. **異動**：同上，於使用者管理調整。
3. **回收**：離職/調職時停用帳號（勿直接刪除，保留 LOG 對應）；檢查其名下場次的「投票管理者」是否需要移轉。
4. **稽核**：每半年比對使用者管理清單與 ISMS 權限名冊（配合 ISMS-04-068）。
5. 管理者密碼原則：至少 8 碼、含字母與數字、不可與帳號或現行密碼相同；密碼修改記 LOG 418。
6. **雙因素驗證（TOTP，選用）**：
   - Migration：`mysql voting < docs/migrations/20260713_users_totp.sql`（部署前備份 `users` 表）。
   - 各管理者於後台「使用者管理 → 雙因素驗證」自行綁定；**不參與登入**，僅強化敏感操作二次驗證。
   - 建議 **sa、va** 等高權限帳號綁定；App 遺失時由 sa 於 DB 重置 `totp_secret` / `totp_enabled`（尚無 recovery code 機制）。
7. **敏感操作與 audit log**（`SENSITIVE_REAUTH=true` 時）：

| 操作 | LOG 類型 | 管理者操作路徑 |
|---|---|---|
| 密碼 CSV 匯出 | 166 | 密碼管理 → 密碼匯出 |
| 選票統計 CSV / 封存單 | 176 | 選票管理 / 檢票 → 選票統計匯出 |
| 列表明文解鎖 / 鎖定 | 167 / 168 | 顯示明文 / 立即鎖定 |
| TOTP 啟用 / 停用 | 422 / 423 | 使用者管理 → 雙因素驗證 |

含明文密碼的匯出須二次驗證（管理員密碼 + TOTP 若已啟用）。操作說明見 [`系統使用手冊.html`](./系統使用手冊.html) §二次驗證與雙因素驗證、§密碼、§選票統計匯出。

## 8. 測試環境維護

測試流程細節見 [`README.md`](../../README.md) 與 [`CLAUDE.md`](../../CLAUDE.md)。維運重點：

- 測試一律加 `--appconfig=config/console-test.php`，否則 fixture 指令會打到**正式庫**。這是本系統最容易出的維運事故，再強調一次。
- **正式環境（`APP_ENV=production`）**：`fixture/load`、`migrate/up` 等危險命令預設被 `ProductionConsoleGuard` 阻擋；若確有必要須設 `ALLOW_PRODUCTION_FIXTURE=1` 或 `ALLOW_PRODUCTION_MIGRATE=1`，並會寫入 LOG 類型 **420**（阻擋）或 **421**（覆寫允許）。
- 測試伺服器：`php -S localhost:8080 -t web web/router-test.php`（走 `index-test.php` 連 `voting_test`）。
- 測試資料庫 schema 需與正式庫同步：正式庫跑過 migration 後，測試庫也要跑（`php yii migrate --appconfig=config/console-test.php`）。
- 測試失敗輸出在 `tests/_output/`，可定期清理。

## 9. 故障排除快查

| 症狀 | 可能原因 | 處置 |
|---|---|---|
| 「請確認有設定環境參數（APP_ENV）」 | `.env` 未載入或 `APP_ENV` 未設 | 檢查 `.env` 存在且 web server 使用者可讀 |
| 登入 403 Forbidden | RBAC 資料不完整（`auth_*` 表） | 檢查 `auth_assignment`/`auth_item`；測試環境重載 `Config,Users,Rbac` fixtures |
| 密碼解密失敗／密碼函亂碼 | 主金鑰錯誤或遺失 | `php yii encrypt/test` 驗證；確認 master.key 與加密當時一致 |
| Bad Request (#400) Host 錯誤 | `ALLOWED_HOSTS` 未含新網域 | 更新 `.env` 的 `ALLOWED_HOSTS` |
| 頁面樣式跑掉 | asset cache 壞掉或權限不足 | 刪 `web/assets/*`，確認目錄可寫 |
| DB 連線失敗 | 密文解密失敗或連線資訊變更 | `php yii config/validate`；重新 `php yii encrypt/db-password` |
| 上傳附件失敗 | filePool 目錄權限/磁碟滿 | 檢查 `APP_PATH_UPLOADS` 權限與磁碟空間 |

更多配置類故障見 [`CONFIGURATION.md`](../CONFIGURATION.md) 的「故障排除」章節。

## 10. Web Server 部署注意事項

以下為依現行程式與設定檔（`config/web.php`、`.env.example`、`SETUP.md`）檢視後，自訂 Web Server 部署時**較容易出問題**的項目。

### 10.1 ALLOWED_HOSTS 未設定（高風險）

`config/web.php` 啟用 Yii `HostControl`，`ALLOWED_HOSTS` 從 `.env` 讀取。若留空，`allowedHosts` 為空陣列，**所有 Host 都會被拒絕**（回傳 404）。

```env
# .env 範例（依實際網域調整）
ALLOWED_HOSTS=voting.example.com,*.example.com,localhost
```

### 10.2 Document Root 必須指向 web/

應用入口為 `web/index.php`。若 Document Root 指到專案根目錄，會暴露 `config/`、`.env`（若未擋）等敏感路徑。`SETUP.md` 範例均設定 `root .../voting/web`。

### 10.3 Pretty URL 與 showScriptName

`urlManager` 設定 `enablePrettyUrl => true`、`showScriptName => true`。在 Apache（`.htaccess`）或 Nginx（`try_files ... /index.php?$args`）正確設定時，外部 URL 通常不含 `index.php`；若 rewrite 未生效，產生的連結可能帶 `index.php` 或路由失效。

短網址規則 `<shortUrl:\w+>` 在根路徑層級匹配，**勿與其他頂層路由名稱衝突**。

### 10.4 子目錄部署（如 /voting/web）

若無法將 Document Root 指到 `web/`，而以子目錄方式掛載（例如 `https://host.example.com/voting/web/`），Yii 需正確推斷 `baseUrl`。現行 `config/web.php` **未設定** `request.baseUrl`，全賴 Web Server 的 `SCRIPT_NAME`；子目錄部署若未額外設定，可能出現：

- 靜態資源（CSS/JS）路徑錯誤
- 表單 action、重新導向 URL 錯誤
- `Unable to determine the path info`（functional test 註解亦有提及）

**建議**：優先採用 Document Root 直指 `web/`；子目錄部署需於 Web Server 與（必要時）`request.baseUrl` 明確設定。

### 10.5 HTTPS 與 Session/Cookie

正式環境（`APP_ENV=production`）下，Session 與 CSRF Cookie 的 `secure` 旗標為 `true`（`config/web.php`）。若前端以 HTTP 存取、反向代理未正確傳遞 HTTPS 資訊，可能導致**無法維持登入狀態**。請在反向代理設定 `X-Forwarded-Proto` 並確認 PHP-FPM 收到正確 scheme。

### 10.6 反向代理與 trustedHosts

`request.trustedHosts` 預設信任 `127.0.0.1/32` 的 `X-Real-IP` / `X-Forwarded-For`。若反向代理在其他 IP，請設定環境變數 `TRUSTED_PROXY_CIDRS`（逗號分隔 CIDR，如 `10.0.0.0/8`），由 `TrustedProxyConfig` 合併至信任清單。

### 10.7 檔案上傳與 filePool 路徑

上傳目錄由 `APP_PATH_UPLOADS` + `APP_ID` 組成（見 `EnvPathConfigTrait`），非 `web/` 底下。Web Server 使用者（PHP-FPM）需對 filePool、`runtime/`、`web/assets/` 具寫入權限。

### 10.8 APP_DOMAIN_* 環境變數

`ConfigInterface` 註解提到 `APP_DOMAIN_PRODUCTION` 等可自訂網域模板，但 `getDomainUrl()` 目前仍回傳常數預設值（`example.com`），**尚未讀取環境變數**。若程式內有使用該方法產生連結，需確認是否符合實際網域，或改以 Web Server 設定的對外網址為準。

### 10.9 部署後驗證清單

```bash
php yii config/validate
php yii encrypt/test
# 瀏覽器：
# - https://{網域}/           → 首頁
# - https://{網域}/admin      → 管理登入
# - https://{網域}/{短網址}   → 場次導向
```
